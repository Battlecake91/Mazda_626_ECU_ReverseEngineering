# External Bus and Memory System

## Bus structure

The ECU has an external 8-bit data bus and at least a 15-bit address bus.

- Address bus: `Adr0..Adr14`
- Data bus: `IO0..IO7`
- ROM: `IC11 27C256`, 32 KiB
- RAM: `IC10 TC5564APL`, 8 KiB
- Bus control generated with `IC20 74HC00` and decoded with `IC17 74HC138`

The EPROM has 32 KiB capacity and uses `A0..A14`. Its outputs connect to the shared data bus.

## RAM: IC10 TC5564APL

The SRAM has 8 KiB capacity and uses `A0..A12`.

Known RAM control pins:

| IC10 pin | Signal / connection |
|---:|---|
| 19 | Connected in bus/peripheral context with IC11/IC4 lines |
| 20 | Connected to IC17 pin 10 |
| 22 | `/OE`, connected to global `/OE` generated by IC20 pin 3 through F2 |
| 26 | `CE2`, connected to `E` / bus-enable net |
| 27 | `R/W`, connected to `R/W` net |

## Important Ghidra address note

During firmware analysis, an address conflict was noted:

- `RAM_EXT` already occupied `0x2000..0x2FFF`.
- Code around `0x998E` references `0x2401` through indexed addressing.

This suggests that firmware-visible RAM or memory-mapped I/O around `0x2000..0x2FFF` must be handled carefully. Not every access in that range should automatically be interpreted as plain external SRAM until chip select logic and firmware behavior are reconciled.

## Likely memory map direction

Current evidence points toward:

- EPROM occupying a large high or fixed program space, depending on MCU architecture and reset vector behavior.
- SRAM decoded into an 8 KiB region.
- Peripheral devices decoded into parts of the external address space through `IC17` and glue logic.
- `IC3 74HC541` likely appears as a read-only external input register at one decoded address range.

The exact address map is still open and should be derived from:

1. `IC17` input pins and enables.
2. `IC17` output routing.
3. `IC20` read/write gating.
4. Firmware access patterns in Ghidra.
5. Logic analyzer captures of address, data and control lines.
